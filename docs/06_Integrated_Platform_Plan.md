# 06 — План интегрированной платформы (после сдачи курса)

> **Статус:** активный план фазы «продукт». Конституция — [docs/00-foundation](00-foundation.md) (ADR-021).
> Курсовая часть (ТЗ: RAG+LLM+Streamlit+Ragas + бонус `student_life`) **сдана** — см. [docs/05](05_Roadmap_and_Priority_Backlog.md) Track A.
> Этот документ — north-star до готовности продукта. Защитная документация пишется **последней**.

## 1. Цель

Одна **интегрированная, монетизируемая, токен-экономная** платформа поступления/сопровождения студента,
а не два разрозненных модуля. Пользователь получает быстрый ответ **бесплатно** (клик), а дорогой LLM
включается только когда в базе нет готового ответа. Это условие прибыльности на старте.

## 2. Что уже есть (и почему сейчас разрознено)

| Компонент | Где | Состояние |
|---|---|---|
| **Движок A — RAG** | `api/main.py` (`/v1/chat`), `generation/`, `retrieval/`, pgvector 586 чанков | ✅ рабочий: гибрид + цитаты + дословный отказ + Ragas (faithfulness 1.0) |
| **Движок B — навигатор грантов** | `poc/grant-recommender/` (`/v1/recommend`, `recommend.py`) | ✅ рабочий POC: 5632 балла 2025 по 87 вузам; **отдельный сервис** |
| **Клик-калькулятор** | `poc/grant-recommender/pitch/grant-navigator.html` | ✅ интерактивный (логика B на JS) |
| **UI** | `ui/streamlit_app.py` → движок A | ⚠️ только A; владельцу **не нравится** (демо-качество) |

**Разрыв:** движки живут в разных сервисах и UI; вопрос «куда пройду со 104 баллами» уходит в движок A
(RAG по документам), где данных о баллах нет → честный отказ. Правильно по логике, но не по продукту.

## 3. Целевая архитектура — 2 слоя (ADR-021)

```
Пользователь
    │
    ▼
┌─────────────────────────── СЛОЙ 1: детерминированный, 0 LLM ───────────────────────────┐
│                                                                                          │
│  ГРАНТ-НАВИГАТОР (движок B)          КЛИК-FAQ (карточки топ-вопросов)                     │
│  балл + предметы → куда на грант     клик по вопросу → готовый ответ + ссылка на источник │
│  (SQL по баллам, детерминизм)        (предрассчитано; контент — из grounded Q/A)          │
│                                                                                          │
└──────────────────────────────────────────┬───────────────────────────────────────────────┘
                                            │  нет готового ответа / свободный вопрос
                                            ▼
┌─────────────────────────── СЛОЙ 2: LLM, только «длинный хвост» ───────────────────────────┐
│  AI-АССИСТЕНТ = движок A (RAG + GraphRAG)                                                  │
│  гибридный retrieval → gpt-4o-mini → ответ с цитатами ИЛИ дословный отказ «кабинет 101»    │
└───────────────────────────────────────────────────────────────────────────────────────────┘
```

**Интент-роутинг (единый бэкенд `/v1/ask`):**
1. Запрос похож на «балл → куда» (есть число ЕНТ + предмет / явный интент) → **движок B** `/recommend`. Дёшево.
2. Свободный вопрос по знаниям → **движок A** `/chat` (RAG+GraphRAG). LLM.
3. **Клик-FAQ** — это UI-уровень: пользователь **кликает** готовый вопрос → мгновенный сохранённый ответ (0 токенов). Печатает свой → идёт в п.1/п.2.

**Экономика:** массовый трафик (типовые вопросы + расчёт баллов) обслуживается Слоем 1 без токенов;
LLM тратится только на уникальные вопросы. Это и есть условие «сможем заработать».

## 4. Что конкретно значит «интеграция»

- **Единый бэкенд.** Логику движка B (`recommend.py`) поднять рядом с движком A под одним FastAPI-роутером
  (`/v1/ask` разводит интенты; `/v1/recommend`, `/v1/chat`, `/v1/faq` — прямые). Целевое (ADR-016): баллы —
  в тот же Postgres, что и вектора; на первом шаге допустимо `recommend.py` как модуль + текущий SQLite/CSV.
- **Единый UI.** Прод-фронт — НЕ Streamlit (ревизия ADR-017). База — `grant-navigator.html` (уже красивый):
  навигатор + клик-FAQ первичны, ассистент-панель — fallback. Streamlit остаётся dev/демо.
- **Общий провенанс/цитаты.** И карточка FAQ, и ответ RAG, и рекомендация B несут ссылку на источник.

## 6. Бюджет и риски

- **OpenAI:** остаток ~$4.3 из $5 (потрачено ~$0.7). Слои 1–2 в рантайме почти бесплатны (навигатор+FAQ = 0).
  Единственная заметная разовая трата — **построение GraphRAG** (TASK-020): предупредить и ограничить объём
  (подмножество чанков / gpt-4o-mini / кэш), либо отложить до пополнения ключа.
- **Точность баллов** (ADR-015): даём как исторические 2025 + провенанс + вероятность, НЕ гарантию.
- **Инварианты сохраняются:** мультитенант `tenant_id` (§2.4), API-first (§2.7), дословный отказ,
  цитаты только из метаданных, judge≠generator в оценке.
- **Не-цель сейчас:** защитные доки (TASK-022) и полировка текста — только после рабочего продукта.
